# SETUP.md — установка окружения

Инструкция для человека без опыта разработки. Делать по порядку,
каждый шаг заканчивается проверкой.

---

## Что ставим и зачем

| Что | Зачем |
|---|---|
| Node.js 22 LTS | среда, в которой работает весь наш код |
| pnpm | менеджер пакетов (ставит библиотеки) |
| Docker Desktop | база данных PostgreSQL локально, без ручной установки |
| Git | уже подключён |

Редактор ставить не обязательно — Claude Code работает сам.

---

## Шаг 1. Node.js

**macOS / Windows:** скачать LTS-версию с https://nodejs.org и установить
обычным установщиком. Соглашаться со всем по умолчанию.

Проверка — открыть терминал и выполнить:

```bash
node --version
```

Должно напечатать `v22.` и дальше цифры. Если команда не найдена —
перезапустить терминал.

---

## Шаг 2. pnpm

```bash
npm install -g pnpm
```

Проверка:

```bash
pnpm --version
```

---

## Шаг 3. Docker Desktop

Скачать с https://www.docker.com/products/docker-desktop и установить.

После установки **запустить приложение** — в трее (Windows) или в
строке меню (macOS) должен появиться значок кита. Он должен быть
активен, иначе база не поднимется.

Проверка:

```bash
docker --version
```

> На Windows при первом запуске Docker может попросить включить WSL2 и
> перезагрузиться. Это нормально, соглашаемся.

---

## Шаг 4. Папка проекта

Распаковать архив в папку проекта. Внутри должны оказаться `README.md`,
`CLAUDE.md`, `SETUP.md`, `PROMPTS.md`, `.gitignore` и папка `docs/`.

Открыть эту папку в Claude Code: в десктопном приложении добавить её
через «+» рядом с полем ввода.

Сразу сделать первый коммит — чтобы документация была в git до того,
как появится код:

```bash
git init
git add -A
git commit -m "Документация проекта"
```

---

## Шаг 5. Инициализация проекта

Это делает Claude Code. Команды для каждого этапа — в `PROMPTS.md`,
копировать по одной.

Начать с самого первого сообщения из `PROMPTS.md` (проверка, что
документация прочитана), затем команда этапа 0.

После инициализации в папке появятся `package.json`, `src/`, `prisma/`
и `docker-compose.yml`.

## Шаг 6. Переменные окружения

В корне проекта будет файл `.env.example` — это шаблон.
Скопировать его в `.env` и заполнить:

```bash
cp .env.example .env
```

Что заполнять:

| Переменная | Откуда взять |
|---|---|
| `DATABASE_URL` | оставить как в шаблоне (локальная база) |
| `OXEN_API_KEY` | sandbox-ключ от Oxen |
| `OXEN_BASE_URL` | `https://api.sbx.oxen.finance/v1/card` |
| `OXEN_RSA_PUBLIC_KEY` | публичный ключ от Oxen (для реквизитов карт) |
| `OXEN_WEBHOOK_SECRET` | секрет для проверки подписи вебхуков |
| `OXEN_MODE` | `mock` на старте, потом `sandbox`, потом `production` |
| `TELEGRAM_BOT_TOKEN` | от @BotFather в Telegram |
| `ADMIN_SESSION_SECRET` | сгенерировать: `openssl rand -hex 32` |

**`.env` никогда не коммитится в git.** Он должен быть в `.gitignore`.
Если случайно закоммитил ключ — ключ считается скомпрометированным,
надо просить у Oxen новый.

Пока ключей нет — ставим `OXEN_MODE=mock` и работаем против заглушки.

## Шаг 7. Запуск базы данных

```bash
docker compose up -d
```

Поднимет PostgreSQL в фоне. Проверка:

```bash
docker compose ps
```

Должна быть строка со статусом `running`.

Остановить базу (данные сохранятся):

```bash
docker compose down
```

---

## Шаг 8. Применить схему базы

```bash
pnpm prisma migrate dev
```

Создаст таблицы. Выполнять заново после каждого изменения модели данных.

## Шаг 9. Запуск

```bash
pnpm dev
```

Админка откроется на http://localhost:3000

Бот и фоновые процессы — отдельной командой:

```bash
pnpm dev:worker
```

---

## Повседневные команды

```bash
pnpm dev              # запустить админку
pnpm dev:worker       # запустить бота и фоновые процессы
pnpm test             # прогнать тесты
pnpm prisma studio    # посмотреть содержимое базы в браузере
docker compose up -d  # поднять базу
docker compose down   # остановить базу
```

3. Полученный токен положить в `.env` как `TELEGRAM_BOT_TOKEN`

## Если что-то сломалось

Порядок действий, прежде чем звать на помощь:

1. Скопировать **полный** текст ошибки.
2. Проверить, запущен ли Docker Desktop.
3. Проверить, что база поднята: `docker compose ps`.
4. Отдать текст ошибки Claude Code целиком, не пересказывая.

Чего не делать: не удалять папку проекта, не чинить вручную файлы в
`node_modules`, не делать `git push --force`.

---

## Про git

Коммитить часто, маленькими шагами, после каждого работающего куска.
Перед рискованными изменениями — отдельная ветка.

```bash
git add -A
git commit -m "что сделано"
git push
```

Никогда не коммитить: `.env`, ключи, дампы базы, скриншоты с реквизитами карт.
