# Команды для Claude Code

Готовые сообщения, которые копируются в Claude Code как есть, по одному
за раз. Следующий этап начинается только после того, как предыдущий
прошёл приёмку из `docs/roadmap.md`.

Фраза «ничего сверх этапа не делай» нужна в каждом сообщении. Без неё
работа убежит вперёд, а фундамент останется недоделанным.

---

## Самое первое сообщение

```
Прочитай CLAUDE.md и все файлы в docs/. Коротко скажи своими словами,
что мы строим и какие правила считаешь главными. Код пока не пиши.
```

Это проверка, что документация прочитана и понята. Если ответ мимо —
значит, что-то в документации непонятно, и это лучше выяснить сейчас.

---

## Прототип

Делается первым, до разработки. Подробности — `docs/prototype.md`.

### П0 — Дизайн-система

```
Прочитай docs/brand.md и docs/design-direction.md, посмотри все
картинки в design/references/. Опиши словами, какое визуальное
направление ты понял и что из референсов мы НЕ берём, прежде чем
писать код.
```

Если описание расходится с тем, что ты видишь на референсах — поправить
сейчас, до вёрстки.

```
Выполни этап П0 из docs/prototype.md: токены по docs/brand.md,
логотип из design/logo/,
тёмная и светлая темы, базовые компоненты, страница-витрина со всеми
компонентами во всех состояниях. Денежной логики не пиши.
Ничего сверх П0 не делай.
```

**Проверка:** витрина открывается, компоненты видны в обеих темах,
значений мимо токенов нет, стиль узнаётся как с референсов.

### П1 — Приложение пользователя

```
Выполни этап П1 из docs/prototype.md. Экраны — по docs/flows-user.md,
состояния и тексты — по docs/states-user.md. Все числа из фикстур,
ничего не вычислять. Ничего сверх П1 не делай.
```

### П2 — Админка

```
Выполни этап П2 из docs/prototype.md по docs/flows-admin.md.
В фикстурах сто пользователей, не три — списки должны проверяться
на объёме. Ничего не вычислять. Ничего сверх П2 не делай.
```

### П3 — Демо-сценарий

```
Выполни этап П3 из docs/prototype.md: панель переключения состояний
и заготовленные персонажи. Любое состояние должно показываться
за два клика. Ничего сверх П3 не делай.
```

### П4 — Показ

```
Подготовь прототип к показу: собери продакшн-сборку и объясни по шагам,
как выложить её по ссылке, чтобы можно было открыть с телефона.
```

После показа правки вносятся в docs/flows-*.md и docs/states-user.md,
и только потом начинается этап 0.

## Этап 1 — Деньги

Самый важный этап. Не торопить и не сокращать.

```
Выполни этап 1 из docs/roadmap.md. Перед работой перечитай
docs/domain-and-money.md целиком. Все обязательные тесты из этого файла
должны проходить. Ничего сверх этапа 1 не делай.
```

**Проверка:** попроси показать результат тестов. Отдельно спроси:

```
Покажи тест на сценарий: внёс 600, потратил 100, внёс 500.
Какой лимит выставляется и почему?
```

Правильный ответ — 1100. Если 1000 или 1600 — ошибка, которая стоит
реальных денег, дальше идти нельзя.

# Полезные команды в работе

**Когда что-то сломалось.** Скопировать полный текст ошибки и отдать
целиком, не пересказывая:

```
Вот ошибка, разберись:
<сюда весь текст>
```

**Когда непонятно, что сделано:**

```
Что ты сделал за последние шаги? Объясни простыми словами, без кода.
```

**Когда кажется, что работа ушла не туда:**

```
Остановись. Сверься с docs/roadmap.md: на каком мы этапе и что из него
ещё не сделано?
```

**Перед тем как закончить работу на сегодня:**

```
Закоммить сделанное с понятным описанием.
```

**Если Claude Code предлагает решение, которое противоречит документации:**

```
Это расходится с <файл>.md. Перечитай его и объясни, почему предлагаешь
иначе.
```

# Чего не делать

- Не запускать несколько этапов одной командой.
- Не говорить «делай дальше всё сам» — потеряется контроль над тем,
  что именно сделано.
- Не принимать этап без проверки из `docs/roadmap.md`.
- Не разрешать отключать тесты, чтобы «пока прошло».
- Не коммитить `.env` и ключи.
